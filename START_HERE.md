# Подключение отдельного Telegram-аккаунта к ежедневному дайджесту ChatGPT

## Что будет работать

- Через MTProto собираются все **доступные** текстовые сообщения, подписи к медиа, даты, ID и ссылки публичных каналов из `channels.json`.
- Первый запуск забирает последние 72 часа, последующие — все публикации с предыдущей успешной проверки с перекрытием в 3 часа. Длинные пропуски сборщика догружаются при следующем успешном запуске, если сообщения ещё доступны.
- GitHub Actions запускает сбор раз в 30 минут (по минутам 07 и 37 каждого часа UTC), сохраняет JSON-посты и отчёты в репозиторий.
- Существующий дайджест ChatGPT впоследствии читает `reports/latest_manifest.json` и все перечисленные в нём JSON-части. Этот последний этап должен быть проверен отдельно.
- Сам архив при использовании **публичного** репозитория будет общедоступен. Добавляйте только публичные каналы.

**Важно**: это не прямое подключение аккаунта к ChatGPT. Telegram-сессию получает только ваш сборщик; ChatGPT получает опубликованные посты. Нельзя обещать 100% воспроизводимость удалённых ранее сообщений, точность запуска GitHub Actions до минуты и загрузку видео/фото в анализ. Сами файлы медиа не скачиваются.

## Однократная настройка без установки программ на домашний компьютер

1. Подготовьте **отдельный** Telegram-аккаунт для чтения новостей. В нём откройте `@bbbreaking` и другие нужные публичные каналы.
2. Зайдите **этим отдельным аккаунтом** на https://my.telegram.org → API development tools. Создайте приложение (один раз) и получите `api_id` и `api_hash`. Не присылайте их ChatGPT.
3. Зарегистрируйтесь на https://github.com и создайте пустой **публичный** репозиторий `telegram-mtproto-archive`. GitHub Actions для публичных репозиториев на обычном hosted runner бесплатен. **Не делайте архив частных переписок публичным**.
4. Распакуйте архив комплекта на компьютере. Загрузите **содержимое** папки в репозиторий. Убедитесь, что файл `.github/workflows/telegram.yml` сохранился по точному пути и что `.env.local` нигде не загружен.
5. В GitHub откройте **Code → Codespaces → Create codespace on main**. В терминале последовательно выполните:

   ```bash
   python -m pip install -r requirements.txt
   python login.py
   python collector.py
   ```

   `login.py` попросит API ID, API hash, телефон и код входа (и облачный пароль, если включена двухэтапная проверка). Все данные вводите только в терминале Codespace, не в чате ChatGPT. Код входа обычно приходит в Telegram на устройство с действующей сессией. Telegram может ограничить авторизацию нового аккаунта; в таком случае проверьте официальное приложение.

6. После успешного первого запуска в терминале должен появиться отчёт по `@bbbreaking`; убедитесь, что `reports/latest_manifest.json` содержит ненулевой `total_messages` и верный отчётный период.
7. В Codespace откройте локальный файл `.env.local`. Он содержит строки `TG_API_ID=...`, `TG_API_HASH=...`, `TG_SESSION=...`. Скопируйте **значения** трёх переменных в **GitHub → Settings → Secrets and variables → Actions → New repository secret** с указанными точными именами. **Не загружайте `.env.local` в GitHub-репозиторий.** Строка `TG_SESSION` даёт полный доступ к авторизованной сессии отдельного аккаунта.
8. В GitHub: **Settings → Actions → General → Workflow permissions → Read and write permissions**, если политика позволяет.
9. В GitHub: **Actions → Telegram MTProto archive → Run workflow**. Дождитесь успешного статуса и появления в репозитории файлов `archive/bbbreaking/...`, `reports/latest_manifest.json`, `reports/latest_index.md`.
10. Только после успешной проверки удалите `.env.local` в Codespace и сам Codespace. Секреты останутся в защищённых переменных GitHub Actions.
11. Передайте ChatGPT **только публичную ссылку** на манифест (без ключей). Она будет вида:

   `https://raw.githubusercontent.com/<YOUR_GITHUB_NAME>/telegram-mtproto-archive/main/reports/latest_manifest.json`

   После этого надо обновить существующую ежедневную задачу ChatGPT на чтение манифеста и перенос выпуска на 07:30–07:45 МСК. Пока это не сделано и не протестировано, автоматическая доставка обзора НЕ настроена.

### Добавить другие каналы

Отредактируйте `channels.json` и добавьте имена публичных каналов без `@`:

```json
["bbbreaking", "another_public_channel"]
```

### Исправление ошибок и восстановление

- **Missing secrets**: неверные имена или пустые `TG_API_ID`, `TG_API_HASH`, `TG_SESSION`.
- **Session not authorized**: сеанс отменён Telegram или вами. Повторите `login.py` и замените `TG_SESSION` в GitHub Secrets.
- **FloodWait**: Telegram временно ограничил обращения. Подождите до следующего запуска и сократите частоту при повторениях.
- **Ошибка `git push`**: проверьте настройку `Read and write permissions`, ветку `main` и защиту ветки.
- **Нет новых публикаций**: откройте `reports/latest_manifest.json` и проверьте `generated_at_utc`, `total_messages`, `all_channels_fetched_after_window`.
- **Нет отчёта ChatGPT**: проверьте, что запланированная задача получила ссылку на архив и действительно может открыть все JSON-части. Это отдельная проблема от работоспособности сборщика.
- По правилам GitHub запланированные workflows могут задерживаться или пропускаться; в публичных репозиториях без активности 60 дней расписание может отключаться. Проверяйте зелёные запуски Actions.

### Безопасность

Строку `TG_SESSION` можно использовать для доступа к Telegram **без повторного SMS-кода**. Не публикуйте её и не пересылайте в чат. При подозрении на компрометацию завершите сеанс в официальном Telegram (Настройки → Устройства), удалите Secrets и авторизуйте новый сеанс. Отдельный аккаунт изолирует остальные личные переписки.
